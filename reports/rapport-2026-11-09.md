### 🛠️ Technique et bonne pratique

**Faites relire chaque modification par un hook `PostToolUse`.** Un hook est une commande que Claude Code exécute à coup sûr à un moment précis, au lieu de compter sur le modèle pour y penser. Avec le matcher `Edit|Write`, votre script tourne après chaque écriture de fichier. Il reçoit sur stdin un JSON dont le champ `tool_input.file_path` donne le fichier modifié. Si le script se termine avec le code `2`, son message sur stderr est renvoyé à Claude, qui corrige dans la foulée. Attention : l'édition a déjà eu lieu, le code 2 ne l'annule pas. Un autre code d'erreur affiche seulement un avertissement.

### 🔌 Outils et intégrations

Les hooks se déclarent à plusieurs niveaux qui se cumulent : `~/.claude/settings.json` (tous vos projets), `.claude/settings.json` (le projet, à versionner pour toute l'équipe), `.claude/settings.local.json` (le projet, ignoré par git), ainsi que dans les plugins (`hooks/hooks.json`) et le frontmatter des skills ou sous-agents. Utilisez la variable `${CLAUDE_PROJECT_DIR}` pour pointer vers vos scripts quel que soit le répertoire courant. Le champ `args` lance la commande sans passer par le shell, ce qui évite les problèmes de guillemets dans les chemins.

### 💡 Exemple d'utilisation

Dans `.claude/settings.json` :
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/check-style.sh", "args": [] }
        ]
      }
    ]
  }
}
```
Et `.claude/hooks/check-style.sh` (nécessite `jq`) :
```bash
#!/bin/bash
FILE=$(jq -r '.tool_input.file_path')
if ! npx prettier --check "$FILE" >/dev/null 2>&1; then
  echo "$FILE n'est pas formaté : lance prettier --write dessus." >&2
  exit 2
fi
exit 0
```
Remplacez Prettier par `dart format --set-exit-if-changed` pour Flutter ou par Spotless pour un projet Spring Boot.

## G. Le défi technique du jour : Un hook qui vérifie le style de chaque fichier modifié par Claude Code

**Niveau :** Intermédiaire · **Durée :** 45 min · **Technologies :** Bash, jq, Biome, React/Next.js

Dans un projet Next.js, installez Biome (`npm i -D @biomejs/biome`) puis écrivez un hook `PostToolUse` (matcher `Edit|Write`) déclaré dans `.claude/settings.json`. Le script lit `tool_input.file_path` sur stdin, ne traite que les fichiers `.ts`, `.tsx`, `.js` et `.css`, lance `npx biome check` sur ce fichier, et en cas d'erreur renvoie à Claude la liste des problèmes sur stderr avec le code de sortie 2. Testez en demandant à Claude d'ajouter un composant volontairement mal formaté et vérifiez qu'il corrige seul.

**Indices :**

- Ignorez les autres extensions avec un simple `case "$FILE" in *.ts|*.tsx|*.js|*.css) ;; *) exit 0 ;; esac`.
- Limitez la sortie renvoyée à Claude (par exemple avec `head -n 30`) pour ne pas saturer son contexte.
- Rendez le script exécutable (`chmod +x .claude/hooks/check-style.sh`), sinon le hook échouera.
