### 🛠️ Technique et bonne pratique

**Protégez vos secrets avec des règles `deny`, pas seulement avec `allow`.** Dans `.claude/settings.json`, Claude Code évalue les règles dans cet ordre : `deny`, puis `ask`, puis `allow`. La première qui correspond l'emporte, quelle que soit sa précision : une règle `deny` large comme `Bash(aws *)` bloque même `aws s3 ls` si celui-ci figure dans `allow`. Ajoutez par exemple `Read(./.env)` et `Read(./secrets/**)` dans `deny` : une règle `Read` en deny bloque aussi `Edit` et `Write` sur le même chemin. Attention, d'après la documentation, une règle Bash compare le texte de la commande, ce n'est pas une barrière de sécurité : un script Python ou Node qui ouvre lui-même le fichier n'est pas bloqué. Pour une vraie isolation, activez le sandbox.

### 🔌 Outils et intégrations

**`ask` pour les commandes à risque.** Une règle `ask` comme `Bash(git clean *)` déclenche une demande de confirmation même si la commande est imbriquée (`cd /tmp && git clean -f`, `$(git clean -f)`), y compris en mode auto. Les règles `deny` acceptent aussi les motifs de noms d'outils : `"mcp__*"` en deny retire tous les outils MCP du contexte de Claude. Les règles se versionnent avec le projet, ce qui permet de partager la même politique avec toute l'équipe.

### 💡 Exemple d'utilisation

Pour un projet Spring Boot ou Flutter, demandez à Claude Code : « Propose un fichier .claude/settings.json qui interdit la lecture de .env, de application-prod.yml et du dossier secrets/, demande confirmation avant git push et git clean, et autorise ./gradlew test et flutter test sans confirmation. Explique chaque règle. » Relisez le résultat, commitez-le, puis testez en demandant à Claude d'afficher .env : la lecture doit être refusée.

## F. Outil à découvrir : OSV-Scanner

Scanner open source de Google qui compare les dépendances de votre projet à la base de vulnérabilités OSV. Il couvre plus de 11 écosystèmes, dont Dart, Java (Maven), JavaScript (npm, yarn) et Python (pip). Une commande suffit : `osv-scanner scan source -r .`. Il propose aussi un mode hors ligne, une vérification des licences (`--licenses="MIT,Apache-2.0"`) et une commande expérimentale `fix` qui suggère des mises à jour pour npm et Maven.

**Pourquoi l'essayer :** En une minute, vous savez si vos projets Spring Boot, Flutter ou Node utilisent une version vulnérable d'une bibliothèque. C'est le complément naturel de Gitleaks (présenté hier) : l'un cherche les secrets, l'autre les dépendances à risque.

🔗 Lien officiel : [https://github.com/google/osv-scanner](https://github.com/google/osv-scanner)

## G. Le défi technique du jour : Signaler les contenus générés par IA dans une liste Flutter

**Niveau :** Débutant à intermédiaire · **Durée :** 45 min · **Technologies :** Flutter, Dart

Créez un écran Flutter qui affiche une liste de morceaux (titre, artiste, durée) chargée depuis un fichier JSON local. Chaque morceau a un champ `aiGenerated` (booléen) et un champ `source` ("humain" ou le nom du générateur). Affichez un badge « Généré par IA » sur les morceaux concernés, ajoutez un filtre (Tous / Humains / IA) en haut de l'écran, et empêchez l'ajout d'un morceau dont le titre contient un nom d'artiste présent dans une liste noire (formulaire avec message d'erreur).

**Indices :**

- Utilisez `rootBundle.loadString` et `jsonDecode` pour lire le JSON déclaré dans `pubspec.yaml`.
- Un `SegmentedButton` ou des `ChoiceChip` conviennent pour le filtre ; gardez l'état avec un `StatefulWidget`.
- Pour la liste noire, comparez en minuscules avec `toLowerCase().contains(...)` dans le `validator` d'un `TextFormField`.
