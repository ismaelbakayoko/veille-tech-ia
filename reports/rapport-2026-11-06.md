### 🛠️ Technique et bonne pratique

**Auditez régulièrement vos plugins et hooks Claude Code.** L'incident Postman de fin octobre (une mise à jour de Postman Desktop avait activé son plugin dans Claude Code et Codex sans demander) rappelle qu'un outil tiers peut modifier votre configuration d'agent. Une fois par mois : listez les plugins installés avec `/plugin`, relisez `~/.claude/settings.json` (plugins activés, hooks `SessionStart`, serveurs MCP) et `~/.claude/plugins/installed_plugins.json`, puis supprimez tout ce que vous n'avez pas installé vous-même. Versionnez la configuration propre à chaque projet dans `.claude/settings.json` pour repérer tout changement avec `git diff`.

### 🔌 Outils et intégrations

**`claude mcp login` / `claude mcp logout`** : authentifiez un serveur MCP configuré directement depuis votre terminal au lieu du menu interactif `/mcp`, et effacez ses identifiants stockés quand vous n'en avez plus besoin. Pratique pour scripter la configuration d'un poste ou d'une CI.

### 💡 Exemple d'utilisation

Demandez à Claude Code de faire l'audit à votre place : « Liste tous les plugins, hooks et serveurs MCP actifs dans ma configuration utilisateur et dans ce projet. Pour chacun, indique d'où il vient, quand il a été installé et ce qu'il exécute au démarrage. Ne modifie rien. » Vous obtenez un inventaire lisible en une minute, puis vous décidez quoi retirer.

## G. Le défi technique du jour : Détecteur de versions Node.js obsolètes

**Niveau :** Débutant à intermédiaire · **Durée :** 45 min · **Technologies :** Node.js (JavaScript), système de fichiers

Écrivez un script `check-node.js` qui (1) affiche la version de Node exécutant le script, (2) parcourt récursivement un dossier de projets passé en argument, (3) repère toutes les lignes `FROM node:<version>` des Dockerfiles et le champ `engines.node` des `package.json`, puis (4) affiche un tableau « fichier / version / statut », où le statut vaut `OK` pour les lignes 22, 24 et 26 et `À METTRE À JOUR` pour toute autre version majeure. Le script doit se terminer avec un code de sortie 1 s'il trouve au moins une version à mettre à jour, pour pouvoir l'utiliser en CI.

**Indices :**

- `process.version` donne la version courante ; `fs.readdirSync(dir, { recursive: true })` simplifie le parcours.
- Une expression régulière comme `/^FROM\s+node:(\d+)/m` extrait la version majeure d'un Dockerfile.
- Bonus : ajoutez une étape GitHub Actions qui lance `node check-node.js .` à chaque pull request.
