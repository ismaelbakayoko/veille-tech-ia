### 🛠️ Technique et bonne pratique

**Mode rapide : l'activer au bon moment.** Dans Claude Code, `/fast` bascule le mode rapide (même modèle, réponses jusqu'à 2,5x plus rapides, prix par token plus élevé). La documentation donne un conseil clé : active-le **au début** d'une session. La première activation dans une conversation facture tout le contexte existant au tarif rapide non mis en cache, et le mode rapide et le mode standard ont des caches séparés. Basculer au milieu d'une longue session coûte donc cher. Réserve-le aux phases interactives (itérations rapides, débogage en direct) et garde le mode standard pour les longues tâches autonomes et la CI.

### 🔌 Outils et intégrations

Le mode rapide se pilote aussi par configuration : `"fastMode": true` dans le fichier de paramètres utilisateur, `claude -p --settings '{"fastMode": true}'` en mode non interactif (v2.1.205+), et `"fastModePerSessionOptIn": true` pour qu'il reparte désactivé à chaque session (utile pour maîtriser les coûts quand tu lances plusieurs sessions en parallèle). La variable `CLAUDE_CODE_DISABLE_FAST_MODE=1` le désactive complètement. Sur un abonnement Pro/Max, il est facturé uniquement sur les crédits d'usage, pas sur les limites incluses.

### 💡 Exemple d'utilisation

Session de débogage d'une API Spring Boot qui renvoie des 500 : lance `claude`, puis `/fast` dès le départ (l'icône ↯ apparaît près du prompt), et itère vite : « lance les tests du contrôleur OrderController, lis la stack trace, propose un correctif ». Une fois le bug corrigé, refais `/fast` pour revenir au mode standard avant de demander « écris les tests de non-régression et mets à jour la doc », une tâche plus longue où la vitesse compte moins. Tu peux aussi combiner mode rapide et effort plus faible pour les petites tâches simples.

## G. Le défi technique du jour : Un routeur de modèles qui choisit entre petit et gros modèle

**Niveau :** Intermédiaire · **Durée :** 45 min · **Technologies :** IA/API — Python ou TypeScript

Inspiré du duo « gros modèle qui planifie / petit modèle qui exécute » : écris une fonction `route(task)` qui reçoit une tâche (texte + type : extraction, classification, refactoring, architecture) et renvoie le modèle à utiliser (un modèle léger ou un modèle haut de gamme) ainsi qu'une estimation du coût. Calcule le coût à partir du nombre de tokens estimé (≈ 4 caractères par token) et d'une table de prix que tu définis dans un fichier de configuration. Ajoute une règle de repli : si le petit modèle renvoie une réponse invalide (JSON mal formé), on relance avec le gros modèle. Écris 5 tests unitaires couvrant chaque type de tâche et le repli.

**Indices :**

- Garde la table de prix dans un fichier JSON/YAML : les tarifs changent souvent, ils ne doivent pas être codés en dur.
- Pour le repli, valide la sortie avec un schéma (pydantic en Python, zod en TypeScript) plutôt qu'un simple try/except sur le parsing.
- Simule les appels aux modèles avec des fonctions factices dans les tests : pas besoin de vraie clé API.
